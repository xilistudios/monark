# redirect/ — the public site

This directory is the **Firebase Hosting document root** (see `../firebase.json`,
`"public": "redirect"`). Its root URL is also the registered Google OAuth
redirect URI, which is why there is no site at `/` and every locale lives under
its own sub-path — `/` must stay free to receive `?code=&state=`.

Everything except the hand-written runtime assets is **generated**. Do not edit
`en/index.html`, `sitemap.xml`, `404.html` or any locale folder by hand; the next
build overwrites it.

## Layout

```
_tools/            build pipeline — never deployed (see firebase.json ignore)
  config.mjs       locale registry + chrome strings
  content.mjs      copy loading / validation
  partials.mjs     <head>, header, footer, language switcher, hreflang
  build.mjs        renders every page, then discovery files
  check.mjs        integrity checks — run after a build
  serve.mjs        local static server with cleanUrls semantics
  locales/*.mjs    one copy set per language
  og/              social card source + renderer
styles.css         hand-written
site.js            hand-written (language dropdown, scroll reveals)
oauth.js           hand-written (root deep-link handling)
favicon.svg/.png   hand-written
og.png             generated by _tools/og/render.sh
fonts/             self-hosted woff2 (latin + latin-ext only)
```

## Build

```sh
node _tools/build.mjs        # render every page + sitemap.xml, robots.txt
node _tools/check.mjs        # verify the emitted site
```

`build.mjs` writes 3 pages per locale (index, privacy, terms) plus the root,
404, legacy `home.html`, sitemap and robots. A locale with no copy set is
**skipped with a warning** and its folder is not written — see below for why
that matters.

`check.mjs` must run *after* a build; two of its checks read the emitted files.

## Add a language

1. Add the locale to `LOCALES` in `config.mjs` (code, label, prefix) and add its
   row to `CHROME` and `SHORT`.
2. Copy `locales/en.mjs` to `locales/<code>.mjs` and translate the strings.
   Keep the key structure and array lengths identical — `check.mjs` fails
   otherwise.
3. Run `node _tools/build.mjs && node _tools/check.mjs`.

Step 2 is not optional in the same commit, but it is *safe* to be late: until
the copy set exists the language is simply not published, and nothing links to
it. That is deliberate — see the `ja` note below.

## Two sources of truth for "which languages exist"

`config.mjs` `LOCALES` is the **registry**: every language the site knows how to
speak. `partials.mjs` `publishedLocales()` is the **subset that actually shipped**.

Anything that *points at* a locale — hreflang alternates, the sitemap, the
language dropdown, the footer strip — must iterate `publishedLocales()`, never
`LOCALES`. `build.mjs` calls `usePublishedLocales()` once before rendering.

This is not theoretical. The site previously iterated `LOCALES` everywhere, so
while the Japanese copy set was still being written the registry advertised
`/ja/` sitewide: 8 hreflang links per page, 3 sitemap entries and a live entry in
every language menu, all pointing at a directory the build never emitted. Every
one of them 404'd, and nothing failed loudly.

`check.mjs` now guards this: it walks the emitted HTML and sitemap and fails if
any internal link, hreflang alternate or `<loc>` does not resolve to a file a
`cleanUrls` host would serve.

## Verify before publishing

```sh
node _tools/build.mjs && node _tools/check.mjs
node _tools/serve.mjs        # http://localhost:4173
```

Verify over **that server, not `file://`**. The root page hops to `/en/`, and
`cleanUrls` paths like `/en/privacy` have no `.html` on disk, so opening the
files directly shows Chrome's own error page rather than the site.

Worth looking at: `/` (OAuth hop), `/en/`, a language menu, `/en/privacy`,
a bad path (404), and dark mode (`prefers-color-scheme`).

## Social card

`og.png` is a 1200×630 render of `_tools/og/card.html`:

```sh
./_tools/og/render.sh
```

It uses headless Chrome rather than ImageMagick on purpose: ImageMagick's SVG
delegate mangles the Inkscape-authored `logo.svg`, and renders text through its
own font stack, so the Newsreader italic in the headline would silently fall back
to a system serif. Chrome applies the exact same CSS, `@font-face` rules and logo
that ship in the site. The card is fixed-size by design — no `clamp()`, no
viewport units, no media queries.

CJK note: the site self-hosts latin + latin-ext only. Japanese and Chinese text
falls back to platform fonts, which is what browsers do anyway — bundling CJK
would add megabytes. On a machine with no CJK font installed (a bare CI
container, for instance) those glyphs render as tofu. That is the environment,
not the site.
